ソース出力の出方鮮度で loss を検出できるか実 heartbeat / 補助信号閾値の目安
AMCL
/amcl_pose・CURRENT		 motion-gated: update_min_d / update_min_a を超える移動時のみ publish できない。完全静止中は無期限沈黙（駐機で偽陽性）・かつ delocalized でも発行を続ける（迷子でも鮮度は正常に見える） 毎スキャン再発行される map→odom TF 秒級 ＋ 静止ゲート必須
cuVSLAM
isaac_ros_visual_slam・TARGET-1 候補		 tracking loss で odometry / TF 出力が完全停止 できる（鮮度が真の loss 検出器になる） /visual_slam/status の vo_state（1=Success / 2=Failed）・/diagnostics の localized_in_exist_map 300ms 級に締める（vo_state=1 のまま約 0.5〜1s 惰性追従する窓を跨がせない）
MOLA-LO
2D LiDAR odometry・TARGET-1（2026-08-17）		 常時 publish: スキャンマッチャは幾何が縮退（一様な壁・廊下）しても出力を止めない できない。解が滑っても出続けるため、鮮度だけでは loss を検出できない（cuVSLAM 型の「止まるから分かる」性質は無い） 自己申告: pose_quality ＋ /diagnostics（＋ ICP covariance の膨張）＝ 追補 A-7 の速い経路 鮮度は補助に留め、主判定は pose_quality 閾値（値は実測で決める＝未定）

OQ-15棚とスキャン面 147.5mm の交差が未確認（スキャン平面の高さで棚がどう見えるか＝MOLA-LO が拾える幾何の量）スキャン面に十分な構造が写らなければ縮退しやすくなる。実測（実機 or 図面照合）が必要
