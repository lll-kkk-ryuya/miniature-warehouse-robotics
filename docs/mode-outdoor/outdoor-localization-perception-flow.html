3. TF ツリーと配信責任（各エッジ 1 ノード・launch 排他・unit pin＝規律は不変）

map（datum 固定の局所直交系） └─ global ekf_node が map→odom を配信（AMCL から交代。navsat_transform は TF を出さない） bot1/odom └─ local ekf_node が odom→base_link を配信（唯一・流用） bot1/base_link ├─ bot1/lidar_link （凍結）／ bot1/imu_link （凍結）／ bot1/camera_link （凍結済・URDF 実測待ち） └─ bot1/gnss_link ★NEW ＝ FROZEN_LINK_NAMES 末尾へ additive（contract PR・robot_dimensions.py） ✗ m1_driver に odom TF を出させない（二重配信の温床）／ ✗ AMCL を起動しない（tf_broadcast:true が global EKF と衝突）
方位（yaw）初期化: 固定経路なので teach 時の A 地点方位を route の datum.yaw に焼き、走行開始後は GNSS 速度由来で補正（磁気は主系にしない・2 アンテナは OQ-OD36）。fix 取得 + heading 収束までは発進禁止を品質ゲートの段に置く。正本: mode-outdoor/03 §4-3。

5. GNSS 品質ゲートと Guardian の pose 源（AMCL 不在で何が壊れるか）

候補鮮度が loss 検出になるか判定
/bot1/amcl_pose（室内 CURRENT・Guardian が直購読）AMCL 不在では最初の pose が来ず pose_age が None のまま → estop は一度も発火せず guard が恒久沈黙屋外では成立しない（必須の変更）
navsat_transform の /odometry/gpsfix を失えば止まるが float でも出続ける△ 補助
global EKF /bot1/odometry/filtered（map）ならない（GNSS が落ちても wheel + IMU で外挿し続ける＝MOLA-LO と同じ「出続ける」性質）○ pose 源の本命・鮮度単独では不可
/bot1/gnss/quality（自己申告・提案）なる（level / h_acc / heading_valid）◎ 主判定。restrict-only（floor より締める方向のみ）を継承。floor 値は OQ-OD39
operational stop と protective stop は別物（doc23 追補 A-3 と同型）: localization ロスト・リンク断・ジオフェンス逸脱は運用停止であり、protective の床（collision_monitor + twist_mux prio100 + L0' クランプ）は地図上の絶対位置に非依存（センサ TF・時刻には依存＝v2.1 語修正）のまま屋外でも 1 枚も減らさない。正本: mode-outdoor/03 §5・05 §0。
