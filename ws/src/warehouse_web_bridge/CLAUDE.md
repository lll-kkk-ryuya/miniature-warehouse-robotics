# warehouse_web_bridge — Web Observability gateway（observe-only・doc22）

- **担当トラック / ブランチ**: `track:web` / `feat/web`
- **Phase**: 3（observe-only console。設計正本 doc22 §13 スライス）
- **編集境界**: このパッケージ配下のみ（＋root `tests/unit/test_web_*.py`）。他パッケージ・共有契約は触らない（契約変更は parallel-workflow §4）。`config/warehouse.base.yaml` の `web_bridge` ブロックは bringup/skeleton 所有＝予告経由（§18#5・S2 PR で追加予定）。
- **消費する契約 (consume)**: doc03 既存トピックの **JSON 文字列のみ**（`std_msgs/String`）。`/state_cache/snapshot`・`/llm/command`・`/llm/reasoning`(生text)・`/character/speech`・`/negotiation/{start,turn,proposal,abort}`・`/emergency/event`（doc03:98-108 / doc22:107-117）。**凍結 pydantic スキーマ / 会話 decoder は import しない**（JSON レベル処理で疎結合維持・doc22:154 / §18#4 は S1/S2 で non-issue）。
- **生産する契約 / トピック (produce)**: **ROS トピックは publish しない**（purely consumer）。提供するのは **ObsEvent 封筒**（WS/REST 上の wire 形・doc22 §5:136-160。ROS 契約ではないので doc03 カタログに producer 追加しない・doc22:119）と、`events-<run_id>.jsonl`（per-run JSON Lines・additive sink・doc22 §9）。
- **依存**: `warehouse_interfaces` ＋ `eval_sdk`（**trace seed 導出のみ**＝`seed_for`/`derive_trace_id`/`derive_plugin_trace_id`/`resolve_run_id`。llm-bridge・orchestrator と同じ一方向 `exec_depend`・doc22:327）。S1 純コアは stdlib のみで両者とも未 import。S2 で `rclpy` + `fastapi`/`uvicorn`/`websockets`（lazy import・nav2_bridge 先例）、`langfuse` は eval_sdk 側の **optional extra**（無ければ trace_id=null に degrade）。**他トラック（`warehouse_*`）内部は import しない**＝Langfuse owner ノブは `warehouse_orchestrator.score_send` を**ミラー**（import しない。cross-lane 突合は unit のみ）。
- **生産する契約（S2 追加）**: HTTP/WS エンドポイント（**同一オリジン :8646**・全て GET / receive-only WS＝observe-only）: `GET /config`（browser-facing 値のみ・secret 非返却 doc22:5.1）/ `GET /events?run_id&since_seq&to_seq&kind&limit`（replay）/ `GET /runs` / `GET /health` / `WS /ws?since_seq`（backfill→live）/ `/`（static SPA・S3 out/ が在る時のみ mount）。entry_point `web_bridge = warehouse_web_bridge.cli:main`（**実行名は不変**。`cli` が heavy-dep preflight を挟んでから `web_bridge_node:main` を import する・#283）。ObsEvent の `trace_id` は **gen_id を持つ negotiation event のみ非 null**（doc22:194・owner ノブ準拠）。さらに **shared run（`WAREHOUSE_RUN_ID` 設定済）でのみ非 null**: 未設定 run は Bridge が session id へ fallback して seed が食い違うため null に degrade（doc22:194,:309）。config `web_bridge`（base: port=8646/snapshot_hz=2、overlay: host/recordings_dir/allowed_origins/static_dir）。
- **テスト**: 偽 publisher 入力 → ObsEvent / events.jsonl / replay を **host pytest**（`test_web_obs_event`・`test_web_event_log`）。S2 純ロジックも host pytest（`test_web_settings`・`test_web_coalescer`・`test_web_hub`・`test_web_views`）。trace 導出は `test_web_trace`（期待値は **doc の seed 文字列を test 側で literal に hash した独立オラクル**・A/D 入替 mutation で赤）、preflight は `test_web_preflight`（cite した `Dockerfile:NN` を**実ファイルで再検証**＝行ドリフトで赤）。**`app.py` / `web_bridge_node.py` は host-test しない**（fastapi/rclpy 非導入＝nav2_bridge 先例）→ 安全は **R-26 no-actuation unit**（`test_web_bridge_noactuation`・AST source-scan: publisher/service/action client/actuation sink/mutating HTTP route ゼロ）で固定。すべて ROS / network / SDK 非依存（doc16 §11）。
- **設計ドキュメント**: [docs/architecture/22-web-observability.md](../../../docs/architecture/22-web-observability.md)（正本）/ 共存パターン [doc12a:200-234](../../../docs/mode-a/12a-integration-mode-a.md) / トピック契約 [doc03:98-108](../../../docs/architecture/03-software-architecture.md)。

## スライス進捗（doc22 §13）

- **S1（本パッケージ初期化・rclpy-free offline core）**: `kind_map` / `obs_event`（ObsEvent 正規化・malformed never-raise・seq 唯一権威）/ `event_log`（append / rotation / retention / `since_seq` replay）/ `ingest`（単一 ingest 点・seq 採番・trace_deriver seam）。R-26 unit 同梱。**trace_id は常に null**（fail-open・Langfuse SDK 非依存・doc22:152,:194。live 導出は S2 以降）。
- **S2（実装済）**: `settings`（config 解決・fail-open default 127.0.0.1/8646/2Hz・browser_config secret 除外）/ `coalescer`（snapshot 10→snapshot_hz・state last-write-wins・rclpy↔asyncio 境界は lock）/ `hub`（per-client bounded asyncio.Queue・snapshot=drop-oldest / event=never-drop→切断・max-clients）/ `views`（events/runs/health 純 read・retention 副作用なし `EventLog.reader`）/ `state`（GatewayState）/ `app`（FastAPI lazy・GET+WS のみ・StaticFiles 後置 mount）/ `web_bridge_node`（rclpy matching-QoS subscribe・snapshot→coalescer・event→ingest+`call_soon_threadsafe(hub.publish)`・2Hz drain・`main()` は rclpy thread + uvicorn）。bind 127.0.0.1。entry_point `web_bridge`。config block を base.yaml + dev overlay に追加（**base は bringup/skeleton 所有＝予告のうえ追加**）。
- **S2.6（本 PR・#433 / #283 web 半分）**: `trace`（trace_id 導出＝Pattern A `derive_trace_id(seed_for(run_id,gen_id))` / Option D `derive_plugin_trace_id` を `WAREHOUSE_LANGFUSE_OWNER` → `hermes.langfuse_owner` → 既定 bridge で選択。不正値は Pattern A に fail-safe・**shared run_id（`WAREHOUSE_RUN_ID`）が無い run／langfuse 不在は null**＝synthetic run_id からは導出しない・scorer `trace_id.py:49-50` と同規則）/ `preflight`（heavy-dep ImportError → pip spec + `deploy/dev/Dockerfile:41-48` の provisioning 位置を示す hint。stdlib のみ）/ `cli`（console script。preflight 後に node を import）。`web_bridge_node` は `Ingestor(trace_deriver=make_trace_deriver(config))` を注入し、`run_id` を `resolve_run_id` 経由にした。**ROS トピック・HTTP surface・ObsEvent の形は不変**（`trace_id` が null から実値になるだけ）。
- **未決の暫定値**: `recordings_dir` は config 注入（具体 SSD path は #187 段階2 後・doc22:379/S6）。rotation 予算（`max_bytes`/`max_runs`）も注入（doc22:221）。`run_id` は S2.5 `/run/header` land まで synthetic fallback（doc22:303）＝**その間 `WAREHOUSE_RUN_ID` を両プロセスに export した run でのみ trace_id が点灯**（`deploy/dev/run-mode-a-live.sh` は現状 export しない＝別レーンの follow-up）。
