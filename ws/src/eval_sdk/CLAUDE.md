# eval_sdk — domain-independent embodied-AI evaluation core

- **担当トラック / ブランチ**: feat/eval-sdk（doc21 Phase 1）
- **Phase**: Phase 1（抽出＋二重利用＝境界の証明。doc21 §10）
- **編集境界**: このパッケージ配下のみ。**ROS / warehouse_\* を import しない**（domain 非依存が存在意義・doc21 §0/§3）。`warehouse_interfaces` 等の凍結契約も触らない。
- **消費する契約**: **なし**。純 stdlib のみ。`langfuse>=4.9,<5` は **optional pip extra**（lazy import・fail-open・rosdep キーにしない・doc21 §12.3）。
- **生産する契約 / API（凍結契約ではない＝doc21 はまだ提案。Phase 2 で `ScoreSpec` 名のみ contract 化）**:
  - `eval_sdk.seed`: `seed_for(run_id, work_id)`（**唯一の決定的 join key**＝旧 `trace_id.seed_for`↔`tracing.trace_seed` の重複を1本化）/ `normalize_trace_id` / `derive_trace_id(seed, *, create_fn=None)` / `resolve_run_id(env_run_id, fallback)`。
  - `eval_sdk.tracer`: `Tracer`(ABC) / `NoopTracer` / `LangfuseTracer(run_id, session_id, provider, mode, extra_tags=None, extra_metadata=None)`。`turn(gen_id)` / `tool_span(name, gen_id)`。**additive（既定空＝後方互換）: `extra_tags`/`extra_metadata`＝caller-supplied OPAQUE labels を `tags=[provider,mode,*extra_tags]` / metadata（reserved `gen_id`/`trace_id` が優先）にマージ**。domain 非依存（prompt/env 等の意味は持たない）。消費者 = Bridge が「どの prompt/env を使ったか」を trace タグ化（doc08 §Langfuse Prompt Management 方針 / doc20 §8）。
  - `eval_sdk.sink`: `FailOpenScoreSink`（generic `score(trace_id, name, value, data_type, metadata=None)` + `flush()` + `from_env(public_key_env, secret_key_env)`、`_fallback_name` フック）/ `DATA_TYPE_{CATEGORICAL,NUMERIC,BOOLEAN}` / `build_client_from_env`。
  - `eval_sdk.stats`: `percentile` / `distance_traveled` / `path_lengths` / `DistanceAccumulator`。**Phase 1.5a 追加（doc21 §14 Step1.5a / §13.1・doc21:299-306）**: nav 成功 `success_rate`(SR) / `spl_metric`(AllenAct verbatim 単episode) / `spl`(SPL 集約・lᵢ≤0 事前フィルタ) / `soft_spl`(SoftSPL) と 平滑性 `low_pass`(**#616 追加・additive**: centered moving average の 'valid' モード＝出力長 `n−window+1`・`window` は正の**奇数**（偶数/非正は `ValueError`）・`window=1` は恒等。`jerk` が :306 のために内部で使う filter と**同一物**に公開名を与えたもので、ドメインが SPARC/LDLJ にも同じ前置フィルタを掛けられるようにする seam。**幅は caller のチューニング値であって domain しきい値ではない**＝doc21:306 は「low-pass する」ことだけを規定する) / `jerk`(3階微分・low-pass先) / `sparc`(SAL・**唯一 numpy 依存＝関数内 lazy import**) / `ldlj` / `n_movement_units`(速度符号反転数)。全て **pre-computed 入力を受ける純関数**（`Sᵢ`/`lᵢ`/`pᵢ` は domain producer が算出・`d_thresh` は domain config＝eval_sdk に入れない・doc21:303）。live 結線(Nav2 goal-reached + planner `lᵢ`)は Phase 3a=scope 外（doc21:245/:312）。**Phase 1.5b 追加（#432・doc21 §14 Step1.5b :407 / §6 :184-186）**: Tier-1 集約算術 `rate`（0 除算→`None`）/ `jain_fairness_index`（Jain, Chiu & Hawe 1984 DEC-TR-301・自前実装＋帰属コメント。空/全ゼロ→`None`・負値→`ValueError`）/ `makespan`（`(start,end)` 列の C_max・end<start は `ValueError`）/ `throughput`（`count/duration`・`duration` が `None`/非正→`None`）。**どれも「何が介入か」「どの負荷が公平か」を知らない**＝指標定義とデータ選択は domain（doc21:178）。消費側の合成は `warehouse_orchestrator.kpi`（`KpiReport.{intervention_rate,command_rejection_rate,fairness_jain}` / `CompletionStats.{makespan,throughput}`）。**doc21 §17 追加（additive）**: `fraction_at_or_below(values, threshold)`（`value <= threshold` の**包含**割合・空→`None`・非有限 threshold は `ValueError`・非有限 value は IEEE 比較のまま＝NaN は分母のみ）/ `trapezoid_integral(times, values)`（**非一様**格子の台形則 `Σ(tᵢ₊₁−tᵢ)(vᵢ+vᵢ₊₁)/2`・2 点未満/非増加時間軸/非有限結果→`None`・長さ不一致は `ValueError`）。**doc21 §17 ③ 追加（#632・additive）**: `TimeSeriesAccumulator(threshold=None)` ＋ snapshot 型 `SeriesTotals`＝上記 2 関数の **streaming 版**（`DistanceAccumulator` の `y(t)` 版）。`add(label,t,y)->bool` は**非有限 `t`/`y` と非前進 `t` を拒否**（最初の点は系列を開き面積 0）し、`totals()` が label ごとに `{samples, at_or_below(threshold 未指定なら `None`), integral, t_first, t_last}` を返す＝**label ごと O(1)**（直前 1 点＋累算値のみ保持）。**しきい値は注入**（非有限は `ValueError`）でドメイン語彙もしきい値も持たない。**ε・速度上限・観測窓はいずれも domain 側**（`warehouse_orchestrator.motion` が doc21 §17 ①② の `idle_ratio`/`speed_budget_utilisation` を窓スコープ = `smoothness_stats` と run 全体スコープ = `run_motion_stats` の両方で合成）。
  - `eval_sdk.cost`: `TokenPrice` / `token_cost(usage, price)` / `resolve_price(model, table, *, default)` / `cost_for_model(...)`（**価格表は注入**＝provider 固有の表は domain 側）。
- **依存**: なし（共有契約にも依存しない）。倉庫が **eval_sdk に一方向依存**する（`warehouse_orchestrator` / `warehouse_llm_bridge` の `package.xml` に `exec_depend`）。
- **背骨（不変条件・verbatim 維持・doc21 §4）**: ① fail-open（creds 無 / SDK 未導入 / 通信障害 → 静かに no-op・raise しない）② lazy-import（langfuse は optional extra）③ 依存注入（`create_fn` / 価格表）→ **SDK 0 / ROS 0 で単体テスト可**。
- **死守する1不変条件**: 「同 `seed_for(run_id, work_id)` → 同 `derive_trace_id` 結果」の property test（`tests/unit/test_eval_sdk_seed.py::test_two_independent_emitters_derive_the_same_trace_id`＝#108/#109→#115 の一般化・doc21 §4/§8）。
- **テスト**: `tests/unit/test_eval_sdk_{seed,tracer,sink,stats,cost}.py`。langfuse 注入 fake / `NoopTracer` / `create_fn` 注入で **langfuse・ROS 非依存**に検証（host `python3.12`、host py3.7 不可）。実 SDK drift は `tests/unit/test_eval_sdk_langfuse_api_contract.py` を `WAREHOUSE_RUN_LANGFUSE_API_CONTRACT=1` で走らせる CI job（`langfuse-api-contract`）に隔離。実 trace の prompt/env tag 永続化は `tests/live/test_langfuse_trace_tags_live.py` を `WAREHOUSE_LIVE_LANGFUSE_TAGS=1`＋Langfuse credentials で手動確認（通常 CI からは分離）。Ruff(py312/line100/double-quote) + pytest 緑を維持。
- **設計ドキュメント**: [docs/architecture/21-eval-sdk-extraction.md](../../../docs/architecture/21-eval-sdk-extraction.md)（§1 決定 / §3 3層 / §4 5モジュール抽出元 / §8 seed 不変 / §10 段階 / §12 再利用方針）。trace_id 契約 = [doc13 §7.5](../../../docs/architecture/13-hermes-setup.md)。比較指標 = [doc08](../../../docs/architecture/08-llm-bridge-common.md)。純コア規約 = [doc16 §11](../../../docs/architecture/16-repository-and-conventions.md)。

## 提供 (produce)
- type/関数: 上記 `eval_sdk.{seed,tracer,sink,stats,cost}` の API（**まだ凍結契約ではない**＝doc21 提案・Phase 2 で `ScoreSpec` 名のみ `contract`）。
